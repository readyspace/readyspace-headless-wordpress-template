# Instantiate and migrate a site

Use GitHub **Use this template** to create one repository per site. Clone it in GitHub Desktop. Create `staging` from `main`, work on feature branches, review a PR into `staging`, deploy and accept staging, then review a PR from `staging` into `main`. The template itself is developed on a feature branch; it does not change any production website.

Record production domain, staging domain, shared CMS origin, cPanel URL/account/app root/runtime, UltimateSales location URL **and API location ID**, brand/locale, all existing integration owners, and the legacy permalink structure. Store secrets in untracked `.env.local` locally and private server files/Node Selector variables. See `.env.example`. A CRM location UI URL is not an API credential.

## Audit before migration

Export all public paths from WordPress/WPGraphQL, crawls, existing Rank Math XML sitemaps, redirects, GSC/Bing/backlink reports (where accessible). Include pages/posts, pagination, category/tag/author/date archives, languages, custom post types, query-based routes, feeds, attachments/media downloads, legacy sitemap paths and hostname-specific pages. Record original status, exact casing/trailing slash, canonical, robots, title/description, schema, images/alt, links, analytics and conversion behavior. Unknown traffic/backlinks remain unknown. Turn `config/url-register.example.json` into your real register; the example is not an inventory.

The starter resolves WordPress URI paths using `nodeByUri`, never relocates posts to `/blog`, and supports native Post/Page/Category/Tag/User plus blog-index ContentType and numbered archive `/page/N/` routes using cursor pagination. Set `WORDPRESS_POSTS_PER_PAGE` to the audited WordPress posts-per-page value (default 10, maximum 100). Menu location defaults to `PRIMARY` and must match the installed theme's GraphQL enum; an explicitly empty location disables CMS menus. Next does not impose a global trailing slash redirect. WP URI normalization and returned canonical must be compared with the site's baseline. `npm run audit:urls -- https://staging.example.com register.json results.json` verifies statuses/canonical paths without submitting forms.

**Per-site work remains required:** custom post types/taxonomies need GraphQL fragments and templates; plain `?p=` permalinks, date archives, feeds, localized/domain routes, custom sitemap names, application routes and legacy redirects need explicit tested adapters. Page-builder CSS/shortcodes/forms/embeds are not reproduced automatically. Content HTML is sanitized; scripts, iframes, unsafe attributes and inline styles are excluded. Rebuild those business features with reviewed React components. Preserve GHL funnels/calendar/checkout links and attribution; a 200 response is not a successful booking/payment/lead test. Never claim all legacy URLs survived based on this generic starter.

Existing upload URLs should remain served by the CMS/webserver under the audited original paths; arrange a fixed-origin uploads proxy or static mapping in cPanel if the public site formerly hosted them. Do not redirect article routes wholesale to the CMS. GraphQL returns media source URLs, binary media delivery is ordinary HTTPS rather than a WordPress data API. Rank Math redirects do not automatically execute on Next; recreate approved redirects in Next/server configuration and test query preservation.

## Acceptance and release

Install the companion plugin and required CMS plugins in the shared `cms.<domain>` instance, verify license/version compatibility, warm **all** required public SEO snapshots using `node --env-file=.env.local scripts/warm-seo.mjs audited-register.json`, revalidate the frontend caches, and run `npm run check:cms` with the private environment loaded. Keep CMS HTML noindex using host response headers, not global WordPress discourage-search indexing (that can leak noindex into Rank Math metadata used publicly). Keep production editorial canonical URL set in companion configuration. Place staging behind authentication/host access restrictions plus noindex: robots alone is not privacy.

Test draft/future/private/password content never enters public pages/sitemaps/SEO; authorized previews render without public caching; editing/publishing/unpublishing/deleting/slugs/Rank Math settings purge both frontend targets; confirm TTL fallback. Compare every audited path's HTML metadata/schema and links. Test mobile/accessibility/performance, consent analytics, authorized CRM test contact receipt, pending confirmation, suppression/unsubscribe and newsletter test delivery with controlled recipients. No real leads/newsletters in generic CI. Review backup/restore, branch checks, app runtime, health and rollback before production approval. Do not switch DNS, migrate Academy, enable newsletter LIVE or merge automatically as template work.

## Technical search and AI visibility

Server-rendered semantic content, correct titles/canonicals/robots, factual JSON-LD, working links and XML sitemaps give crawlers usable content. Rank Math editorial settings remain authoritative through the GraphQL snapshot adapter. Do not fabricate ratings, FAQ answers, courses or business facts, nor promise search/AI ranking. Optional `llms.txt` needs reviewed site-specific text; it is not a required SEO standard. Submit verified production sitemap URLs to GSC and Bing after site acceptance; preserve verification and account ownership.
